# Plus + GPT-5.5 High + Fable5-Method Style Workflow

This document defines a practical workflow for using ChatGPT Plus with a high-reasoning setup and a Fable5-method style operating discipline.

It does not unlock a different model. It improves output quality by enforcing better planning, evidence checking, verification, and risk control.

## Recommended daily setup

Use this stack:

```text
ChatGPT Plus
GPT-5.5 Thinking or highest available reasoning mode
High reasoning / extended thinking when available
This repository instruction file
Obsidian or Markdown notes for reusable prompts and project memory
GitHub for portfolio and code evidence
```

## Core principle

The model should not only answer. It should work through a reliable loop:

```text
Inspect -> Plan -> Execute -> Verify -> Score -> Decide next action
```

## Standard task prompt

Use this prompt for serious work:

```text
Use a careful senior-engineer workflow.
First inspect the available evidence.
Separate facts, assumptions, and guesses.
Give a short plan before the final answer.
Score the result by performance, stability, risk, setup difficulty, and recommendation.
End with the single best next action.
Do not claim something was tested or verified unless it actually was.
```

## For coding tasks

Use this prompt:

```text
Review this like a senior engineer.
Find the root cause first.
Do not rewrite broadly.
Make the smallest safe change.
Explain what files should change and why.
Include verification steps.
Call out remaining risks.
```

## For business or career tasks

Use this prompt:

```text
Evaluate this by money potential, portfolio value, execution difficulty, risk, and long-term leverage.
Give a score out of 100.
Pick one best option.
Say what to do today.
Say what to avoid.
```

## For external work messages

Use this prompt:

```text
Rewrite this so it is ready to send.
Make it natural, concise, and professional.
Avoid overpromising.
Keep the tone practical.
Give a score and a final send-ready version.
```

## Scoring standard

Use this scale:

| Score | Meaning |
|---:|---|
| 95-100 | Best practical option; only minor tradeoffs |
| 90-94 | Strong option; recommended |
| 80-89 | Usable but has limits |
| 70-79 | Experimental or situational |
| 60-69 | Risky or unstable |
| Below 60 | Avoid unless there is a special reason |

## Recommended operating rules

1. Avoid tool obsession. Output must lead to action.
2. Use GitHub for visible proof, not only storage.
3. Use Obsidian for private knowledge, prompts, and decision logs.
4. Use ChatGPT for reasoning, drafting, review, and execution planning.
5. Use external automation only when it is stable, legal, and worth the setup cost.
6. Keep every project small enough to finish.

## Best current workflow

```text
1. Ask ChatGPT with high reasoning.
2. Force evidence-first reasoning.
3. Save reusable prompt or output to Obsidian.
4. Turn useful work into a GitHub file, README, sample, or case study.
5. Use the result for portfolio, external work, or job applications.
```

## Definition of done

A task is complete only when it has at least one of these outputs:

- A send-ready message
- A completed README
- A working sample script
- A portfolio asset
- A checklist with next action
- A verified fix
- A decision with one selected option

## User-specific priority

For this user, always prioritize:

```text
Money potential
Portfolio value
External-work value
Automation leverage
Immediate execution
```

Avoid vague advice. End with a decision.
